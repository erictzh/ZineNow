## Intro

**Data** (the table button next to the Layers button in the tool bar) is a **mail merge**: you design one page, put **fields** in its text, connect a spreadsheet, and ZEditor makes **one page for each row**. Use it for letters, invitation cards, name cards, certificates, or any page that repeats with different words. This is the Basic part; everything stays on your device.

## How to use

*(New to this? The Data panel starts with a three-step reminder, and **Or try it with 5 made-up rows** loads a tiny sample so you can try everything at once.)*

**Excel files:** the same button also takes an **.xlsx** workbook. If it has several sheets you choose which one (name and number of rows shown); hidden and empty sheets are not offered. Row 1 is the column names, as with CSV. Dates come in as dates (`2026-12-08`, with the time if the cell has one), numbers without the `.0`, and a formula gives the value it last showed. Colours, fonts, pictures and merged-cell layouts are ignored, and the old **.xls** format and password-protected workbooks cannot be opened (save as .xlsx or CSV). The rows are kept inside the project as text, so the workbook is not needed afterwards.

1. Save your sheet as a **CSV** file (in Excel or Google Sheets: *Save as / Download → CSV*). The **first line must be the column names**, then one line per row.
2. Click the **Data** button (the table icon beside Layers), then **Choose CSV file…** (or **Or paste the rows here**). The file is kept **inside your project**, so it travels with the .znow file.
3. Design your page. In a text box, write a field in double curly brackets, like `Dear {{name}},`, or click a **field chip** in the Data panel: it adds the field to the selected text box, or to a new one.
4. **Preview**: with *Show this row's words on the page* ticked, the page shows the chosen row's words. Use ◀ ▶ to step through rows. (A box you are typing in shows its field names, so you can edit it.)
5. **Order**: *As in the file*, or, if your sheet has a column named **id**, *lowest first* or *highest first*.
6. **Make pages**: choose which rows (leave blank for all), then **Make N pages**. The new pages go right after your designed page, which is **hidden** (crossed-out eye, so it is skipped when exporting) unless you untick that.
7. **Make pages for rows … to …**, **Hide the page you designed** and the warnings sit under the panel with the Make button (the same on both tabs).
8. Changed your design or data? Go back to the designed page and **Make pages** again: the pages made earlier are **replaced** (it asks you to click once more to confirm). The made pages are ordinary pages: you can edit them by hand, but a re-merge replaces them.

- Under the panel you are told if the page uses a field the file has no column for, or if some rows are empty in a field.
- A field can have a **filter**: `{{name|upper}}`, `{{name|title}}`, `{{price|number}}`, `{{date|date:d MMMM yyyy}}`, `{{city|default:Malaysia}}`. Also `lower`, `trim`, `first`, `pad:3`.
- One undo step undoes the whole merge.
- Not yet: a page-size switch for the sheets.

## Advanced: data blocks and groups

Under the file name at the top of the Data panel there are two tabs, **Basic** and **Advanced** (the file and the tabs stay in place while the rest scrolls). Basic is the default; the tab you leave open is remembered in your browser.

- A **data block** is a group of items that shows **one record** (a photo, a name, a role). Select its items, group them (**Ctrl+G**), then **Mark the selected group as a data block**. Or, once data is connected, use the **⋮** menu on the group's row in the Layers panel: **Make data block** (a small *data* tag then shows on the group's row; the same menu says **Not a data block** to undo it). Copy the block (select it, **Ctrl+C**, **Ctrl+V**; a pasted block lands 20 px down and right, so drag it to where you want it) as many times as you want on the page: each copy is a **slot**, filled in reading order (rows from the top, each left to right) with the next record. 10 records with 5 slots make 2 pages; empty slots on the last page are left out.
- Everything else on the page is a **non-data item**. Fields in it show the group's first row, plus `{{page in group}}`, `{{pages in group}}` and `{{records in group}}`.
- *(Hidden for now.)* **Make a grid of copies** (would show when a data block is selected): choose **Columns**, **Rows** and a **Gap (mm)**, then the button. The block stays in the top-left cell and the copies fill the rest, one block width plus the gap apart. Size the block to one cell first (name card, label) and put it where the first cell should be. Or pick a **Sheet** (name card 90 × 55, address labels 3 × 7 or 2 × 7, invitation A6, picture gallery 3 × 4): the block moves to the sheet's first cell and the copies follow the sheet's exact cell spacing. The panel warns if your page is not the sheet's size (they are A4), or your block is bigger than one cell. Label sizes are a guide: check them against your own sheet and print one test page on plain paper first. The panel tells you if some of the grid runs off the page. It is one undo step.
- **Pictures** (Advanced tab): put a **different photo** on each page or block. Add a column that holds each photo's file name (`ana.jpg`; the extension and capital letters may be left out). **Choose photo folder…** (or **Or choose photo files**) keeps the photos inside the project, shrunk to at most 1600 px on the longest side (PNG stays PNG, the rest become JPEG). Put an ordinary picture on your page as the frame, select it, and under **Selected picture shows the photo named in** choose the column. Each made page then shows that row's photo, cropped to fill the frame and centred. The preview shows it too. If a row has no photo name, or no file with that name, the picture is **left out** (never someone else's photo) and the panel warns you. Many large photos make the project file big: every made page carries its own copy.
- **Calculated columns** (Advanced tab): **+ New column** makes a column from the ones in your file, chosen from a menu (no formulas to type): *Row number* (start and digits, in the order of the pages), *Join columns* (up to three, with a space, comma, dash or slash between), *Initials*, *First or last word*, *Capital letters* (UPPER, lower, Title), *Add words before or after* (RM before a price), *Calculate with a number* (add, subtract, multiply, divide), *Age from a date* (whole years today) and *Part of a date* (year, month name, month number, day). A sample line shows what row n gives before you add it. The new column appears among the fields like any other, and is saved in the project. (Ordering by `id` only looks at columns from your file.)
- **QR types** (the Format panel's **Type** list for a QR code): *Website*, *Phone call*, *SMS*, *Email*, *WhatsApp*, *Wi-Fi*, *Contact card*, *Map location* and *Custom text*. Pick one and fill in a few labelled boxes; ZEditor builds the text the phone reads (`tel:`, `mailto:`, `WIFI:T:WPA;S:…;P:…;;`, a vCard, `geo:`…). Every box can use `{{column}}`; text around the fields is made safe (spaces in a subject, `;` or `:` in a Wi-Fi password) while the fields stay for the merge to fill. A Website with no `https://` gets it (also for addresses that come from your data). A type with its main box empty makes no code. *Custom text* is the old single box, and the Data panel's QR box makes Custom text.
- **QR tool** (tool bar, the little QR icon after the Image tool; works without any data): click it and a square **QR code** appears in the middle of the page. Its **Format panel** has a **QR code** box with the focus already in it: type a web address or any text and the code is drawn at once (a static code, for a website, a phone number, a Wi-Fi name). With `{{column}}` in the text (for example `https://example.com/{{id}}`) the page shows a **grey QR** until data is connected; then the preview shows each row's code and every made page gets its own. A QR with no text is left out of made pages (the panel says so). It is an ordinary picture: move it, resize it (it stays square), copy it, put it in a data block. The same text can also be edited in the Data panel (Advanced tab → Pictures).
- **QR codes** (Advanced tab → Pictures): put an ordinary picture on your page as the frame, select it, and in **Or make it a QR code of** type the text the code should hold, with `{{column}}` where a value goes, for example `https://example.com/{{id}}`. Each made page gets its own code, drawn **square and centred** in the frame (black on white, with the quiet border scanners need, error correction M). It also shows in the preview. If a field is empty or missing for a row the code is **left out** (it would point to the wrong place) and the panel says how many. A picture is either a photo field or a QR code, not both. **Print one and scan it with a phone before you print many**; codes work best at least about 2 cm across.
- **Group by** a column (for example `band`): each value starts on a new page, then fills its slots. Without it, records just fill the blocks page after page.
- **Page designs → Add continuation design** (Advanced tab, when the page has data blocks): adds a **copy of your page** right after it, for **pages 2 onward of a group**. Change the copy like any page: delete the title, add or remove blocks. Page 1 of each group is made from the first page, the later ones from the copy, so with 5 blocks on the first and 6 on the copy a group of 14 makes pages of 5, 6 and 3. A group that fits on the first page uses only the first design. Without a copy, the first design is reused for every page (use *Show on* to hide the title on later pages). On the copy, the panel says so, and **Not a continuation design** turns it back into an ordinary page; **Open the continuation design** jumps to it from the first page. Both are hidden when you make pages (with the tick), and both go into a data template. The counts and warnings read the blocks and fields of both pages.
- **Flowing list** (Advanced tab; directories, timelines, price lists): entries of **different heights** stacked down the page, a new page when the next one does not fit. Design **one entry** (group its items, for example a name, a position and a line under them) and press **Mark the selected group as the list entry**; draw a **rectangle** where the list may flow and press **Mark the selected rectangle as the list area** (it is not drawn on the made pages). Text boxes in the entry that have **no fixed height** grow with each row's text, and what is below them (or overlaps them sideways) moves down by the growth, so a long position never covers the line under it. An entry is **never split** across pages; one taller than the whole area gets a page of its own and the panel warns. **Space between entries (mm)** sets the gap. Page 1 uses the first design's area, later pages use the **continuation design's** own entry and area (Add continuation design copies both; change the area there, for example taller with no title above it). Show on, page counters, photos and QR codes work as in blocks. **Columns** (1 to 4, with a gap in mm): the list fills down the first column, then the second, then the next page; design the entry inside one column's width (the panel warns when it is too wide). **Group headings:** design a heading (a group, for example `{{group}} team` and a line), press **Mark the selected group as the group heading**, then choose **Group by**: each group starts with the heading, filled from the group's first row, and the heading is **never left alone at the bottom of a column** (it moves on with its first entry). Tick **Start each group on a new page** if you want that. Not available with *Export each record as a PDF* (a page holds many rows).
- **Long text** (Advanced tab; letters): draw one text box with the Text tool (it needs a **fixed height**), put your fields and the long text in it, select it and tick **The selected text box continues on the next page when it is full**. When you make pages, each record's text is cut where the box is full: a short record stays on **one page**, a long one carries on in a second page, and a third if needed (up to 30). The cut is at the start of the first line that does not fit, so no word is split. Page 2 onward are made from the **continuation design** (Add continuation design, then mark its text box as the long text too), or from the same page again if you add none. `{{page in group}}` and `{{pages in group}}` give "Page 2 of 3" per record, and *Show on* works (for example an address block on the first page only). The text is cut as plain text into ordinary pages, so you can still edit every page. The panel warns when the long-text box has no fixed height. This is used when the page has no data blocks.
- **Export each record as a PDF…** (under the Make button, after you have made pages): one **PDF per record** with all of that record's pages (so a letter that needed two pages gives a two-page PDF, a short one a one-page PDF). Set a **File name** pattern with fields, for example `{{id}} {{last name}}` (the default is your first column, or `id`); the dialog shows the first names. Names that come out the same get ` (2)`, ` (3)`; characters a file name cannot hold become spaces. Then **Save as a zip**, or **Save to a folder…** (Chrome and Edge on a computer). Page numbers restart in each PDF. Not available for pages made with data blocks, because one page holds several records.
- **Repeat non-data items on the other pages** (ticked by default): the title, footer, logo and so on show on every page of a group. Unticked, they show on the group's first page only.
- **Selected item shows on**: for one non-data item, choose *Every page*, *First page of the group*, *Continuation pages only* or *Last page only*. It overrides the tick box for that item.
- The preview shows the chosen row in the first block, the following rows in the next blocks, and hides blocks with no record left.

## Data templates (sharing a design)

A **data template** is a design someone else can fill with their own spreadsheet: name cards, labels, certificates.

- **Project → Save as data template…** saves a copy named **`ZDATA = <title>.znow`** (for example `ZDATA = Name cards.znow`). It holds your designed pages and merge settings (Group by, Repeat non-data items) but **not the spreadsheet and not the photos**, and it leaves out the pages a merge made. The file is also marked as a template inside, with the list of columns it needs. Your own project is not changed.
- **Opening** a data template asks: **Use this template** opens a copy that is not saved anywhere yet (so the template file is never overwritten) with the Data panel open, which says which columns your CSV needs; **Edit it** opens the template itself, and **Save** keeps it a template (no data, no photos).
- Share it like any file. System fonts are **not** put inside a template, so the other person needs them (or sees a stand-in); fonts you uploaded travel with it.

## How it works

### Reading the file

`.xlsx` is a zip of XML files: `io/zipReader.js` lists the zip's files and inflates them with the browser's own `DecompressionStream` (no library), `model/dataMerge/xlsx.js` reads the shared strings, the cell styles (which show a date) and the sheet rows with a small scanner (so it also runs in the tests), and `io/xlsxReader.js` turns each visible sheet into CSV text.

`model/dataMerge/csv.js` reads commas, semicolons, tabs or bars, quoted cells with line breaks, and a leading byte-order mark. Duplicate or empty column names are made unique.

### Filling the text

`model/dataMerge/fields.js` (`fillTemplate`) replaces each `{{field}}` with the row's cell, applying filters. A field with no column stays visible as written. `model/dataMerge/build.js` (`mergeAnnotations`) copies a page's items with new ids (groups and linked text follow), filling the text boxes. A box whose length changes loses letter-by-letter colouring, which no longer lines up.

### Pages

`model/dataMerge/groups.js` (Advanced) finds the slots (`dataSlots`), groups the records (`groupRecords`), plans the pages (`planPages`) and fills one (`mergeGroupPage`; `showsOnPage` decides Show on). A data block's items carry `dataBlock: true` and a non-data item may carry `showOn`; made pages carry neither.

`model/dataMerge/build.js` also has `makePhotoFinder` (cell text to photo), `fillCrop` (centre-crop to the frame), `fillPictureItem` and `pictureProblems`; `io/dataPhotos.js` reads and shrinks the photos. A picture item with `picField: "column"` is the frame.

`model/dataMerge/template.js` names the file (`templateFileName`), keeps the designed pages (`templatePages`), lists the columns needed (`templateNeeds`) and drops the data and photos from the settings (`templateSettings`). The marker is `dataTemplate: { version, columns }` in the project file (`io/projectFile.js`); `state/useProject.js` asks "use or edit" when it finds one (`DataTemplateDialog.jsx`) and keeps `editingTemplate` so Save keeps a template a template.

`sheetGrid` turns a ready-made sheet (`GRID_PRESETS` in `layout.js`) into pixels; `gridCopies` takes its cell spacing as `pitch`. `model/dataMerge/calc.js` holds the calculated columns (`CALC_KINDS`, `calculate`, `applyCalculated`; tested); `ui/panels/CalcColumns.jsx` is the menu form. They are added after any ordering, in `useDataMerge`.

`planPages` takes `slotCount` and `nextSlotCount` (the continuation design's slots) and marks each page `design: "first" | "continuation"`; `cloneItems` copies the page; the copy carries `dataFor` (the key of the page it is for) and `useDataMerge` finds it with `continuationPage`.

`io/qrImage.js` (`qrPatch`: the text and picture a QR item stores, with a grey `qrPlaceholder` for empty or field text; the QR tool is `handleAddQr` in `useAnnotationEdits`, the text box is `format/QrSection.jsx`) draws the code with `qrcode-generator` (MIT; credited in THIRD-PARTY-NOTICES) as a 16-pixel-per-module PNG, cached by text. `fillQrItem` (`build.js`) swaps a picture item that has `qrText` for its code; `qrProblems` counts the rows that leave it out.

`model/dataMerge/flow.js` splits a record's long text across pages (`splitFlowText`, `planFlowPages`, `mergeFlowPage`; the measuring is `fitLength` in `render/textFit.js`, which finds the first line the box hides). A text box with `flowText: true` is the long text.

`model/dataMerge/export.js` groups made pages by record (`recordGroups`, using `mergedFrom`, `mergeRow` and `mergeRecord` on each made page) and names the files (`recordFileNames`); `io/zipWriter.js` is a small dependency-free zip writer (stored, UTF-8 names); `state/useDataMerge.js` `exportRecords` builds each PDF with the normal PDF exporter on that record's pages only.

`model/dataMerge/list.js` holds the flowing list: `layoutEntry` (how far each item of an entry moves down for a record's text), `packList` (entries into pages) and `buildListPage`; `useDataMerge` measures with `itemBox`/`textHeightFor` (`render/textFit.js`). Items carry `listEntry: true` / `listArea: true`; a design with both is `listMode`, which comes before data blocks and letters.

`gridCopies` lays out the grid of copies (`makeGrid` in the hook measures the block with `annotationBounds`; mm to pixels is mm / 25.4 x 72 x 1.1).

`state/useDataMerge.js` keeps the parsed rows, the order and the preview row. Made pages carry `mergedFrom` (the designed page's key) and `mergeRow`; that is how a re-merge finds the pages to replace. The preview is only drawn (`ComposeCanvas` `mergeRecord`); the page's own text is never changed by it.

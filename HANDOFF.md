# ZineNow — Context & Handoff

Read this first when resuming on another machine. It covers what the project is, how it's built, what was done, what's pending, and the testing gotchas that cost the most time.

New to the code? Start with **[docs/MAINTAINING.md](docs/MAINTAINING.md)** (how to work on it, where things are, recipes) and **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** (structure and rules).

Last updated: 2026-11-17 (after the modular refactor and the magic eraser).

## 1. Project overview

ZineNow is a suite of browser-only tools for making zines. Everything runs from static files: open via `file://` or any static server. Apps being refactored into modules (see [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)) have a `src/` folder that `npm run build` (esbuild) turns into a committed `dist/app.js`. Using the apps needs no build; changing an app with a `src/` folder does.

| App | Path | Purpose |
|---|---|---|
| ZEditor | `apps/ZEditor/src/` (built to `dist/app.js`) + `index.html` + `styles/` | Edit PDF pages: text, images, drawing, filters, page management. Saves editable `.znow` projects. |
| ZineArranger | `apps/ZineArranger/src/` (built to `dist/app.js`) + `index.html` + `style.css` | Imposes a multi-page PDF into a printable zine booklet. |
| Md to PDF Converter | `apps/Markdown-to-PDF/src/` (built to `dist/app.js`) + `index.html` + CSS | Markdown → paginated PDF eBook. |
| Shared | `shared/vendor/` (pdf.js, pdf-lib), `shared/styles/` (tokens and components, linked by each page before its own CSS), `shared/js/` (hand-off, download fallback) | Code and styles more than one app uses; see docs/ARCHITECTURE.md. |
| Launcher | `index.html` (root) + `launcher/` (`launcher.js`, `launcher.css`, `bg.jpg`); app list in `config/apps-config.js` | Landing page linking to the apps. (`app-logo.png` referenced by it is missing — pre-existing 404, harmless.) |

## 2. Architecture notes per app

### ZEditor (single ~3400-line file)
- React (UMD globals) app whose code is split across `src/` (`model/`, `render/`, `io/`, `state/` hooks, `ui/` — see docs/ARCHITECTURE.md for which hook owns what), built by `npm run build` into `dist/app.js`. Function names mentioned below are unchanged (except `renderThumb` → `renderPdfThumb` in `render/pageRender.js`, and `buildExportPdfBytes(pages, pdfDocsRef, pageNumbers)` in `io/pdfExport.js`); search `src/` for them. No Babel in the browser any more. pdf.js (rendering) and pdf-lib (export) come from the shared copies in `shared/vendor/`.
- **State is immutable everywhere** (`.map` / spread, never mutate). Undo snapshots rely on this for structural sharing — keep it that way.
- Page object: `{ key, docId, pageNumber, rotation, dataUrl, isBlank, annotations, filter }`. Blank pages have `width/height` instead of `docId/pageNumber`.
- `pdfDocsRef.current` = `{ docId: { doc, bytes } }` — multiple source PDFs can be loaded (Insert PDF). Use `docFor(pdfDocsRef, page)`.
- Undo/redo: call `recordUndoCheckpoint(coalesceKey?)` BEFORE a mutating `setPages`. Same key within `UNDO_COALESCE_MS` (700ms) merges into one step. Thumbnails (`dataUrl`) are stripped from snapshots and regenerated.
- Annotations: types `text`, `image`, `rect`, `stroke`. Edited through `updateAnnotationsFor(pageIdx, updater, coalesceKey)`. The `page.annotations` array is the stacking order (first = bottom), for both the editor and export; `.znow` files older than version 2 are re-sorted on load. `hidden` and `locked` items can't be selected.
- **Filters (grayscale/duotone/halftone) are per-page** (`page.filter`, default `DEFAULT_PAGE_FILTER = {type:"none"}`), edited via `updatePageFilter(pageIdx, patch)`. Images have their own `ann.filter` (`match` = follow the page's filter). Both preview and export read `page.filter`.
- Export: `buildExportPdfBytes()` renders every page to canvas (`renderPageToCanvas`) and embeds PNGs via pdf-lib.
- Project file `.znow` = JSON (base64-embedded source PDFs + pages minus thumbnails + settings). Self-contained; thumbnails regenerated on load.
- Selection model: primary `selectedIdx` / `selectedAnnId` + secondary arrays `selectedPageIndices` / `selectedAnnIds` (Shift+Click multi-select).
- Keyboard shortcuts (window `keydown` effect): Delete, Space=Select, T, I, H, D=Draw, Ctrl+Z/Y, Ctrl+R (rotate), Ctrl+C/V (internal annotation copy/paste), ArrowUp/Down (page nav), Escape (leave text editing but keep selected). A separate `paste` listener handles pasting an image from the system clipboard.
- Page reorder in the sidebar uses native HTML5 drag-and-drop (`Sidebar` → `dragHandlersFor`); annotation dragging uses manual mouse listeners — different mechanisms.

### Md to PDF Converter
- JSX source in `src/` (settings/, document/, convert/, export/, io/, editor/, ui/ — see docs/ARCHITECTURE.md), built by `npm run build` into `dist/app.js`. The old hand-converted `App.jsx` and the `window.MD2eBook` global are gone; `pdfGenerator.js`'s functions now live in those folders under the same names. `defaultConfig.json` and `sample.md` are still plain `<script>` files (globals `MD2eBookDefaultConfig`, `MD2eBookSampleMarkdown`) loaded before the bundle, so they can be edited without a build.
- Normal export (`exportToPdf` in `src/export/printExport.js`) uses the browser's native print dialog (`window.print()` in a hidden iframe). It never yields PDF bytes in JS — the code comments explain it deliberately avoids html2canvas.
- Live preview: `renderHtmlDocument()` in a `sandbox="allow-scripts"` iframe (opaque origin, on purpose) paginated by Paged.js; talks to the parent only via `postMessage`.
- Depends on CDNs (marked, mammoth, turndown, jszip, pdf-lib, DOMPurify, Tailwind, React, Google Fonts, Paged.js, html2canvas) — needs internet.

### ZineArranger
- Plain JS (no React) in `src/`, built to `dist/app.js` (see docs/ARCHITECTURE.md). All changing values live on one `state` object (`src/state.js`); `index.html`'s `onclick`/`onchange` attributes call functions that `src/main.js` puts on `window`. Imposition is data: `src/imposition/layouts.js` (one entry per size/sides/orientation/spine) read by `impose()`; it replaced a 4,770-line hand-written function and was checked byte-identical against it.
- The "ZEditor handoff" block is in `src/main.js` (message types imported from `shared/js/zineArrangerHandoff.js`): listens for `postMessage` `{type:"zeditor-handoff-pdf", buffer, filename}` and feeds the bytes into its `#selector` file input; pings `{type:"zinearranger-ready"}` to `window.opener` every 500ms (up to 15×).

### Cross-app handoff protocol ("Send to ZineArranger")
Sender: `sendPdfToZineArranger(buildBytes, filename)` in `shared/js/zineArrangerHandoff.js`, used by ZEditor (`src/state/useExport.js`) and Md-to-PDF (`src/ui/App.jsx`). It does:
1. `window.open("../ZineArranger/index.html","_blank")` synchronously in the click handler (popup-blocker safe).
2. Attach a `message` listener **immediately** (before any `await`) for `zinearranger-ready`.
3. Build PDF bytes, await ready, then `win.postMessage({type:"zeditor-handoff-pdf", buffer, filename}, "*", [buffer])`.
The message type is named after ZEditor but ZineArranger doesn't check the sender, so Md-to-PDF reuses it as-is.

Pipeline: hidden iframe → Paged.js paginates → html2canvas rasterizes each `.pagedjs_page` at scale 2 → images `postMessage`d back → pdf-lib assembles a PDF → handoff to ZineArranger.

### Md-to-PDF typography changes (2026-11)
- Fixed stretched last lines in justified text: Paged.js stamps `text-align-last: justify` on the `.page` wrapper and paragraphs inherit it (`paginationJustifyFix` in `src/document/styleBlock.js`).

## 5. Testing setup and gotchas (read before debugging "it's stuck")

Dev server: any static server rooted at the project folder, e.g. `python -m http.server 8951 --directory "<path to ZineNow>"`, then open `http://localhost:8951/apps/ZEditor/index.html`. Under Claude Code's preview tooling this is done via a `.claude/launch.json` in the session's primary working directory (not necessarily the project folder). Remove it when done.

Things that looked like bugs but weren't:
- **Hidden browser pane throttles `requestAnimationFrame`** → pdf.js rendering, Paged.js and html2canvas appear to hang. Taking a screenshot foregrounds the pane briefly; it reverts to hidden between tool calls. Poll with screenshot + wait inside one `browser_batch`, and keep patience (Paged.js + html2canvas take ~10–30s here).
- **HTTP cache is sticky**: after rebuilding `dist/app.js` etc., a plain reload kept serving the stale script, even in a new tab. Use a **new port** (new origin) or a cache-busting query on the page; note sub-resources (`<script src="pdfGenerator.js">`) do not inherit the page's query string. Verify with `fn.toString().includes("...")`.
- **`window.open(_, "_blank")` in the test pane replaces the current tab**, destroying the sender before it can finish the handoff. Not representative of a real browser.
- The network-request tool only logs same-origin requests; CDN loads never appear. Console history can persist across navigations.
- Loading a PDF into ZEditor without a file dialog: build a `File`, put it in a `DataTransfer`, assign to the hidden `input[type=file][accept="application/pdf"]`, dispatch `input` + `change`. A tiny test PDF can be made in-page with `PDFLib`.
- Capturing Export/Save output: set `window.showSaveFilePicker = undefined`, monkey-patch `URL.createObjectURL` to stash the Blob, click the button, then inspect the blob (e.g. render pages with `pdfjsLib` and sample pixels).
- Since the modular refactor, each app's code is one bundled `dist/app.js` (an IIFE), so functions such as `renderPageToCanvas` are **not** reachable from the console any more. To exercise a pure function, bundle it for Node with esbuild (as was done for the ZineArranger imposition check), or drive the UI. ZineArranger's `onclick` handlers are the exception: `src/main.js` puts them on `window`.

## Print typography, steps 3b, 4, 5 (2026-11-18, scheduled run)
**How it was built** (details in docs/ARCHITECTURE.md, "Threaded frames" and "Text wrap"): renderers still draw one box at a time; a new page-level step, `resolvePageText(annotations)` in `render/pageText.js`, turns the page's items into boxes that can each be drawn alone. Everything that draws or measures text goes through it: the editor (`ComposeCanvas`), page pictures and thumbnails (`renderPageToCanvas`), Export (`io/pdfExport.js`, picture and vector), the Format panel (`App.jsx` passes the resolved box), Ctrl+C. A page with no thread and no wrap gets the very same array back, and with the features off every changed code path computes the same numbers as before (composer: same widths and indents, x + 0; layout: the added blocks only run with `storyLength`, `verticalAlign`, `wrapObstacles` or `columnRule`), so existing text should draw pixel-identically. That was checked by reading the code paths and by the Node tests, not by pixel hashes in a browser (see "NOT verified" below).
- **Step 3b, threaded frames (done):** the head box holds the story; followers have `threadFrom` and no text (`model/text/threads.js`). Out-port on a frame (bottom-right): red + = overset text, click to continue it in a new frame; grey + on a selected fixed-height frame; ▸ = already linked (in-port ▸ top-left on followers). Text panel > Columns & frame: "Link to next frame" / "Unlink next frame" and "Frame n of a threaded story". Linking makes the box a fixed frame (keeps its current width/height) and puts a same-size frame to its right, or below if there's no room. Typing, selecting, colouring letters or changing the look in any frame edits the story; frame settings (position, width, frame height, columns, gap, vertical align, column rule: `FRAME_PROPS`) stay per frame. Deleting a frame relinks its neighbours; deleting the head hands the story to the next frame (`removeWithThreads`). Moving frames needs nothing (frames keep their ids). Empty followers survive leaving edit mode and show a dashed edge. Copy/paste of a frame pastes a plain box with the words that frame shows. Rasterize is disabled on threaded frames. Same page only; Ransom/Curve/Stacked text can't thread.
- **Step 4, text wrap (done):** Image and Shape panels > Text wrap: None / Around bounding box / Around object shape, Wrap offset (pt, default 6). Object shape = the image's opaque rows (alpha >= 24, read in 96 bands by `render/wrapShapes.js`, crop and rotation honoured) or an ellipse's outline (Ellipse shapes, images with the Ellipse edge). Every text frame the item overlaps sets each line in the widest free stretch beside it (InDesign's "largest area"); a line with less than 1.5 em free moves down in quarter-line steps. Works with justify, indents, hyphenation, both composers, columns (incl. balanced), frames and threads. The composer got `slotFor(para, line)` / `onParagraph`; `flowAroundObstacles` in `render/textLayout.js` places the lines.
- **Step 5, polish (done):** frame-height drag handles (top- and bottom-middle, on every ordinary text box); Vertical align Top/Centre/Bottom (fixed-height frames, per column; ignored while text wrap affects the frame); Column rule (line between columns, weight in tenths of a pt, colour #1a1a1a, drawn on the canvas and as a vector line in the PDF); Export preflight: the notice also says "Overset text: a text frame on page N has more text than fits" (missing font files were already reported there).
- **Verified:** `npm run build`, `npm run check` (up to date) and `npm test`: 7 test files, all pass. New: `tests/threads.test.js` (chains, loops, duplicate followers, follower view, patch routing incl. colour runs, deleting middle/head/two frames, copy, composer continuation), `tests/wrap.test.js` (free slots incl. offset, scale and slanted edges; box/rotated/ellipse/cropped-row outlines; alpha rows; which items become obstacles; composer slots with both composers; flow beside, below, jumping past, columns and overflow), `tests/pageText.test.js` (the real `layoutText` with a fake 0.5-em canvas: a 3-frame story shows every word exactly once and in order, no indent on a continued paragraph, last-frame overflow, resolving twice is a no-op, plain pages come back unchanged, wrap beside and below an image keeps every word).
